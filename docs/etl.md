# ETL-конвейер Corporate Data Platform

## Инструмент

Для оркестрации обработки данных используется Apache Airflow 3.1.0. Сервисы запускаются через Docker Compose.

## DAG

Идентификатор: `corporate_etl`.

Задачи выполняются последовательно:

```text
extract_companies → transform_companies → load_report
```

Передача результата одной задачи в следующую создает зависимость в Airflow.

## Источник данных

PostgreSQL, база `corporate`, таблица `companies`. Подключение настраивается переменными `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`.

Извлекаются поля `id`, `name`, `industry`, `city`, `employees`.

## Этапы ETL

- **Extract —** читает организации из PostgreSQL, сортируя их по идентификатору.
- **Transform —** группирует организации по городам и рассчитывает количество компаний, суммарное и среднее число сотрудников.
- **Load —** перезаписывает CSV-отчет `airflow/output/companies_by_city.csv`.

Среднее округляется до двух знаков после запятой. Городские строки сортируются по названию.

## Расписание

DAG запускается ежедневно (`@daily`). `catchup=False` запрещает Airflow создавать запуски за пропущенные периоды. Тестовый запуск также можно выполнить вручную в веб-интерфейсе.

## Запуск и проверка

Из корня проекта:

```bash
docker compose up -d db
docker compose up -d airflow
docker compose ps
docker compose logs --tail=50 airflow
```

Веб-интерфейс: [http://localhost:8081](http://localhost:8081). При первом запуске Airflow standalone выводит пароль пользователя `admin` в журнал контейнера.

После запуска DAG проверьте все три задачи со статусом `success` и содержимое `airflow/output/companies_by_city.csv`. Для проверки обновления результата измените или добавьте запись в таблице `companies`, повторно запустите DAG и сравните CSV.

## Результат для исходных данных проекта

```csv
city,company_count,total_employees,average_employees
Riga,2,790,395.0
Tallinn,2,305,152.5
Vilnius,1,210,210.0
```

Результат вычислен по пяти строкам из `database/init.sql`. После изменения данных в PostgreSQL его нужно пересоздать запуском DAG.

## Контрольные вопросы

1. **Что означает ETL?** Extract, Transform, Load: извлечение, преобразование и загрузка данных.
2. **Что выполняется на Extract?** Данные читаются из источника; здесь — строки таблицы PostgreSQL `companies`.
3. **Какие операции выполняются на Transform?** Очистка, фильтрация, объединение, изменение формата, расчет признаков и агрегация. Здесь выполняется группировка по городам и расчет показателей.
4. **Что означает Load?** Сохранение подготовленного результата в целевом хранилище или файле; здесь — CSV.
5. **Каков источник?** PostgreSQL, таблица `companies`.
6. **Каков результат?** `airflow/output/companies_by_city.csv` с количеством организаций и статистикой сотрудников по городам.
7. **Для чего используется Airflow?** Для оркестрации задач: расписания, порядка выполнения, повторных запусков и контроля статусов и журналов.
8. **Почему применяют оркестратор вместо одного скрипта?** Скрипта достаточно для простой разовой обработки, а оркестратор упрощает расписание, контроль ошибок, повторные запуски, историю выполнения и управление зависимостями.
9. **Что такое DAG?** Directed Acyclic Graph — направленный ациклический граф задач и зависимостей.
10. **Почему граф направленный?** Каждая зависимость задает направление выполнения от предыдущей задачи к следующей.
11. **Что означает ацикличность?** В графе нет замкнутых циклов зависимостей.
12. **Чем DAG отличается от Task?** DAG описывает весь процесс; Task — отдельную операцию внутри процесса.
13. **Какие задачи входят в `corporate_etl`?** `extract_companies`, `transform_companies`, `load_report`.
14. **Почему Transform не запускается раньше Extract?** Transform получает результат Extract как вход, поэтому Airflow сначала выполняет извлечение.
15. **Как Airflow определяет зависимость?** По передаче XCom-результата одной декорированной задачи в следующую.
16. **Для чего `schedule="@daily"`?** Для ежедневного планового запуска DAG.
17. **Для чего `catchup=False`?** Чтобы не выполнять автоматически все исторические интервалы, пропущенные до включения DAG.
18. **Почему `airflow/logs` исключен из Git?** Журналы создаются при каждом запуске, быстро растут и не являются исходным кодом проекта.
19. **Чем Airflow отличается от Kubernetes?** Airflow управляет последовательностью и расписанием задач обработки данных; Kubernetes запускает и поддерживает контейнеризированные приложения и их масштабирование.
20. **Что будет при ошибке Extract?** Зависимые последующие задачи не выполнятся успешно; Airflow отметит ошибку и сохранит журнал выполнения.
